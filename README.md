# VaultKeeper — сейф для папок в Windows

Программа, которая **полностью убирает выбранные папки из Windows**: файлы
шифруются AES-256-GCM и уезжают в контейнер, а сама папка **удаляется с диска
целиком** — вместе с именем. Без пароля её нет ни в проводнике, ни в диалоге
«добавить файл» в браузере или Telegram, ни в поиске, ни в «Недавних файлах»,
**даже если включить показ скрытых элементов**: искать просто нечего.

Новые файлы, брошенные в защищённую папку, **прячутся сами** — за пару секунд,
без ручной блокировки (см. «Новые файлы прячутся сами»).

Неверный пароль **не выдаёт ошибку**: приложение ведёт себя так, будто пароль
верный, папки на это время появляются с файлами-приманками, а нападающий не
узнает, что ошибся.

Интерфейс — как мобильное приложение: тёмный градиент, крупные карточки,
нижняя навигация, анимации. Сборка — один файл `VaultKeeper.exe`.

---

## Что именно происходит с папкой

| Шаг | Действие |
|---|---|
| 1 | Папка обходится; symlink/junction **не проходимся** (нельзя стереть данные за пределами папки) |
| 2 | Каждый файл шифруется в отдельный блок (`AES-256-GCM`, куски по 4 МиБ, свой nonce на кусок) |
| 3 | Блок перечитывается и сверяется по sha256 и размеру — **до** удаления оригиналов |
| 4 | Только после проверки оригиналы перезаписываются мусором и удаляются |
| 5 | Папка убирается с диска целиком (настройка «Полностью убирать папки»); приманки создаются только на время сеанса с неверным паролем |
| 6 | Чистятся следы: ярлыки «Недавних», прыг-списки быстрого доступа, MRU в реестре, кэш эскизов |

Имена файлов, пути и размеры лежат только внутри зашифрованного манифеста —
в файловой системе видны лишь безымянные блоки `*.vkb`.

## Почему папка именно удаляется, а не «скрывается»

Атрибут «скрытый» в Windows не защищает ни от чего: достаточно включить показ
скрытых элементов — и папка снова видна, а диалог выбора файла в браузере
показывает их по умолчанию. Поэтому VaultKeeper не маскирует папку, а
**убирает её из файловой системы**:

* папки нет в проводнике, в «Этот компьютер», в поиске, в диалогах
  «добавить файл» (браузер, Telegram, почта), в списке «Недавних»;
* у постороннего нет даже имени папки — оно лежит в зашифрованном манифесте;
* чтобы папка снова появилась, нужен пароль (или аварийный ключ).

Если полное удаление не подходит (например, программа-клиент требует
существования каталога), в настройках можно выключить
«Полностью убирать папки» — тогда на месте папки останутся приманки, как
в первой версии.

## Новые файлы прячутся сами

Пока приложение работает (в окне или в трее), оно раз в 2 секунды смотрит
защищённые папки в **закрытом** состоянии:

| Ситуация | Что происходит |
|---|---|
| Ключ в памяти (настройка «Мгновенно прятать новые файлы» включена) | Новый файл сразу шифруется в контейнер, оригинал стирается, папка снова убирается |
| Ключа в памяти нет | Файл уносится в скрытый буфер `<сейф>\stage` (атрибуты H+S) и зашифруется при следующем открытии сейфа |
| Сейф открыт | Файлы **не трогаются** — вы с ними работаете |

Файл считается готовым к переносу, когда его размер стабилен между двумя
проверками, — идущее копирование не прерывается. Приманки, которые приложение
положило само, не переносятся.

Компромисс: «Мгновенно прятать» означает, что мастер-ключ живёт в памяти
процесса, пока приложение в трее. При убийстве процесса через Диспетчер задач
файлы остаются зашифрованными, но дамп памяти живого процесса теоретически
может содержать ключ. Если это критично — выключите настройку: тогда новые
файлы будут уходить в скрытый буфер и шифроваться при вводе пароля.

## Режим обманки (неверный пароль)

* Вводится неверный пароль → интерфейс показывает «Доступ открыт» и список
  защищённых папок с их размерами (витрина обманок).
* Папки на это время **создаются заново** с приманками внутри — всё выглядит
  рабочим и проверяемым через проводник или диалог выбора файла.
* Любые изменения в таком сеансе молча игнорируются: настоящий контейнер
  даже не расшифровывается.
* При возврате к закрытому состоянию (кнопка «Заблокировать», автоблокировка
  или выход) приманки убираются, а папки снова исчезают с диска.
* Экран ввода пароля ничем не намекает на существование обманок.

## Закрытие через Диспетчер задач

Поведение настраивается («Настройки → Аварийный доступ»), по умолчанию —
**«Вернуть всё как было»**:

* Убили, пока файлы были **открыты** → они так и остаются открытыми на диске.
* Убили, пока всё было **зашифровано** → при следующем запуске приложение
  замечает аварийный выход и возвращает файлы в открытый вид без пароля,
  используя аварийный ключ DPAPI (привязан к вашей учётной записи Windows —
  на чужом ПК или под другим пользователем он не сработает).
* Варианты «Спросить при запуске» и «Оставить заблокированным» дают больше
  защиты ценой удобства.

Данные при этом не теряются ни в одном сценарии: каждое действие пишется
в журнал, а оригиналы стираются только после полной проверки шифрокопий.

## Восстановление доступа

1. **Пароль** — основной способ.
2. **Код восстановления** (`XXXX-XXXX-XXXX-XXXX`) — показывается один раз при
   создании сейфа и при ротации; храните на бумаге. Открывает сейф без пароля.
3. **Аварийный ключ DPAPI** — вход без пароля в той же учётной записи Windows
   (кнопка «Аварийный доступ» или `VaultKeeper.exe --recover`).

Смена пароля переупаковывает только мастер-ключ и занимает секунды —
данные не перешифровываются.

## Установка и запуск

### Из исходников (любая ОС, для разработки)

```bash
pip install -r requirements.txt
python -m vaultkeeper            # окно приложения
python -m vaultkeeper --selftest # быстрая проверка шифрования в консоли
```

### Сборка .exe (только в Windows)

```bat
build\build.bat
```

или вручную:

```bash
pip install -r requirements.txt pyinstaller pillow
python build/make_icon.py        # иконка
python build/build_exe.py        # → dist\VaultKeeper.exe
```

`.exe` — один файл, без консоли, с иконкой; запуск двойным кликом или
`VaultKeeper.exe --minimized` (сразу в трей).

### Первый запуск

1. Придумайте пароль (минимум 4 символа, лучше 12+ с разными регистрами).
2. Сохраните показанный код восстановления.
3. Вкладка «Папки» → «Добавить папку» → выберите папку. Она исчезнет,
   оставив приманки.
4. Вкладка «Приманки» — положите туда пару правдоподобных документов.
5. Кнопка «Заблокировать всё» прячет открытые файлы; пароль на экране
   блокировки снова открывает их.

Горячая клавиша **Ctrl+Alt+Shift+L** — мгновенная блокировка из любого окна.
Иконка в трее: двойной клик — показать окно, средняя кнопка — заблокировать.

## Консольные команды

```bash
VaultKeeper.exe --status                 # состояние хранилища и прошлого сеанса
VaultKeeper.exe --lock                   # заблокировать всё (спросит пароль)
VaultKeeper.exe --recover                # вернуть файлы без пароля (DPAPI)
VaultKeeper.exe --recover-code КОД       # вернуть файлы по коду восстановления
VaultKeeper.exe --selftest               # самопроверка шифрования
VaultKeeper.exe --vault ПУТЬ             # другое расположение хранилища
VaultKeeper.exe --theme light            # светлая тема
```

`--recover` и `--lock` работают даже если графика не запускается — это
страховка на случай проблем с драйверами или профилями.

`--status` дополнительно показывает, сколько файлов лежит в скрытом буфере
и ждёт шифрования при следующем открытии сейфа.

## Модель угроз и честные ограничения

**Защищает от:** близких и коллег за вашим ПК; приложений, которые шарят по
диску (браузеры, мессенджеры, облачные синхронизаторы папок); «Недавних файлов»,
быстрого доступа, поиска Windows и кэша эскизов; простого копирования диска
другим человеком (контейнер зашифрован).

**Не защищает от:**

* **Администратора/другого пользователя с вашим паролем Windows** в сценарии
  «аварийный возврат = авто»: DPAPI-ключ доступен тому же пользователю ОС.
  Выберите «Оставить заблокированным», если это ваш сценарий угрозы.
* **Следов на SSD**: wear-leveling и теневые копии могут сохранить старые
  блоки удалённых файлов. Полная гарантия — только шифрование всего диска
  (BitLocker) поверх VaultKeeper.
* **Дампов памяти/файла подкачки/гибернации**, снятых пока файлы открыты.
  Пока сейф открыт, файлы лежат на диске открытыми — иначе ими нельзя
  пользоваться. Автоблокировка по таймеру сокращает это окно.
  Включённая «Мгновенно прятать новые файлы» держит мастер-ключ в памяти,
  пока приложение работает в трее (иначе новые файлы не спрятать без пароля) —
  выключите её, если дамп памяти живого процесса входит в вашу модель угрозы.
* **Копий, которые вы сами сделали** до защиты (облако, резервные копии,
  отправленные файлы). Проверьте их отдельно.

Хранилище по умолчанию лежит в `%LOCALAPPDATA%\VaultKeeper\vault` — этот
каталог не синхронизируется облаками профиля. Не переносите его в OneDrive.

## Структура проекта

```
vaultkeeper/
  core/            # без Qt: криптография, контейнер, файлы, следы
    crypto.py      # PBKDF2/HKDF/AES-GCM, упаковка ключей, код восстановления
    blob.py        # потоковое шифрование файлов кусками, аутентификация
    vault.py       # оркестрация: защита папок, журнал, аварийный возврат
    decoys.py      # склад приманок и «витрина» для режима обманки
    traces.py      # Recent, прыг-списки, MRU, эскизы, индекс поиска
    fsutil.py      # обход без symlink, безопасное стирание, атомарная запись
    win.py         # DPAPI, реестр, оболочка, единственный экземпляр
  ui/              # PySide6: мобильный интерфейс
  config.py        # настройки (settings.json без секретов)
  __main__.py      # GUI + консольные режимы
tests/             # 105 тестов ядра и интерфейса (headless)
tools/ui_preview.py# рендер скриншотов интерфейса без Windows
build/             # сборка .exe и иконки
```

## Разработка

```bash
pip install -r requirements.txt pytest
pytest tests/ -q                                  # тесты ядра и UI (headless)
QT_QPA_PLATFORM=offscreen python tools/ui_preview.py out/   # скриншоты экранов
```

Формат контейнера версионируется (`VKH1`/`VKB1`); манифест хранится с
резервными копиями, при повреждении выполняется откат на свежую копию.
